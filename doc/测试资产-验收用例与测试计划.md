## 2. 单元用例（纯函数，开发自测门禁）

测试对象为《技术资产-研发侧技术方案预研.md》3.1 / 3.2 的两个纯函数，**前端不得存在实现副本**（1.2 约束），故仅需在服务端侧覆盖。

### 2.1 计分与原型映射

| 用例 | 输入 | 期望 | 关联需求 |
|---|---|---|---|
| TC-SC-01 | 10 题全选 A | 原型码 `AAAA`，映射曜日型 | 3.2 / 3.5 |
| TC-SC-02 | 10 题全选 B | 原型码 `BBBB`，映射夜幕型 | 3.2 |
| TC-SC-03 | Q1A Q2B Q3A Q4B Q5A Q6B Q7A Q8B Q9A Q10B | 原型码 `ABAB` → 双星型（题库资产 §四 自检链路） | 3.2 |
| TC-SC-04 | D3 取 Q3B、Q7A（1:1 同分） | D3 位取 `A`（理性） | 3.5 同分判定 |
| TC-SC-05 | D4 取 Q4B、Q8A（1:1 同分） | D4 位取 `A`（主动） | 3.5 同分判定 |
| TC-SC-06 | 答案不足 10 题 / 含非法选项 | 返回 `ANSWER_INCOMPLETE` / `ANSWER_INVALID`，**不生成结果** | 3.2 / 6 |
| TC-SC-07 | 同一组答案连续调用两次 | 两次结果完全一致（无随机成分） | 3.2 结果确定性 |
| TC-SC-08 | **穷举 2¹⁰ = 1024 组答案** | ① 输出恒为 16 个合法码之一；② 出现同分的仅 D3、D4；③ 无异常分支 | 3.2 / 3.5 |

> TC-SC-08 为**发版门禁脚本**，非人工用例：脚本失败即阻断构建（与《技术资产-研发侧技术方案预研.md》12 章自检清单一致）。

### 2.2 同频度

| 用例 | 输入（双方原型码） | 期望 | 关联需求 |
|---|---|---|---|
| TC-SM-01 | `ABAB` / `ABAB` | C = 4、P = 0、100%、同频共振型 | 3.5 |
| TC-SM-02 | `ABAB` / `ABAA`（1 处异端） | C = 3、P = 1、91.7%、高默契型 | 3.5 |
| TC-SM-03 | `ABAB` / `AABB`（2 处异端） | C = 2、P = 2、83.3%、均衡互补型 | 3.5 |
| TC-SM-04 | `ABAB` / `BABA`（全异端） | C = 0、P = 4、66.7%、极致互补型 | 3.5 |
| TC-SM-05 | 遍历 16 × 16 = 256 组配对 | ① 恒有 C + P = 4；② 展示值恒为 {100, 91.7, 83.3, 75, 66.7} 五值之一；③ 标签恒由 C 决定（同 C 必同标签） | 3.5 |
| TC-SM-06 | 同 C 但不同码组合 | 标签恒定不变，**不出现按百分比排序或优劣判定** | 3.5 / 视觉口径 |
| TC-SM-07 | 任一侧码长度 ≠ 4 | 返回 `CODE_INVALID` | 6 错误码 |

> TC-SM-05 为批量校验用例（可脚本化）；`75%` 一档由 C = 1 命中，须在用例中显式覆盖，避免被 5 档中的中间档漏测。

## 3. 集成与端到端用例

### 3.1 主流程

| 用例 | 步骤 | 期望 | 关联需求 |
|---|---|---|---|
| E2E-01 单人完整链路 | 入口进入 P-01 → 开始 → P-02 → P-03 答完 10 题 → P-04 | 结果卡正常生成，原型名 / 符号卡 / 特质解读与原型码一致；免责可见 | 3.1 / 6 |
| E2E-02 配对完整链路 | P-04 发起配对 → 生成配对码与邀请卡 → 好友经分享进入 → 完成本人测试 → P-05 | 图谱绘制双方 4 维度对照，同频度与相处模式叙事与该组合的 C 值一致 | 3.1 / 3.3 / 3.5 |
| E2E-03 分享四渠道 | 依次拉起 抖音好友 / 抖音群 / 保存图片 / 复制配对码 | 四个渠道均可拉起；失败时有兜底提示；**未分享不影响结果可见** | 7.2 / 线稿说明 P-06 |
| E2E-04 关键词表扫描 | 在文案常量中临时注入一个禁用词，触发构建 | 构建失败（门禁生效）；移除后恢复正常 | 4.3 / 8 |

### 3.2 异常与边界（PRD 3.6 六场景逐条）

| 用例 | 步骤 | 期望 | 关联需求 |
|---|---|---|---|
| TC-SS-01 中途退出恢复 | 答至第 5 题退出，重新进入 | 提示「继续上次答题」，恢复至第 5 题位，已答答案不丢 | 3.6 |
| TC-SS-02 提交失败幂等 | 断网后提交 → 恢复网络重试；重复提交 3 次 | 重试成功；服务端**不产生重复结果** | 3.6 / 6 |
| TC-PA-01 邀请过期 | 将 `expires_at` 置为过去 → 进入 P-05 | 展示「已过期」态并提供重新发起入口；`PAIR_EXPIRED` | 3.3 / 3.6 |
| TC-PA-02 受邀者未完成 | 发起后不完成对方测试，停留在 P-05 | 展示等待态与再次提醒分享入口 | 3.3 / 3.6 |
| TC-SS-03 重复进入结果页 | 连续多次进入 P-04 | 每次结果一致，以首次计算结果为准，不重新随机 | 3.6 |
| TC-SS-04 题库版本不一致 | 用旧版本会话提交至新版本接口 | 返回 `QUIZ_VERSION_MISMATCH`，提示重新开始，**不迁移旧答案** | 技术方案 3.4 |

### 3.3 配对状态机专项（并发与幂等）

| 用例 | 步骤 | 期望 | 关联需求 |
|---|---|---|---|
| TC-PA-03 并发接受同一码 | 两个不同账号同时对同一 `pair_code` 调 `acceptInvite` | 仅一方写入成功，另一方得到明确错误；不产生脏数据 | 技术方案 3.3 |
| TC-PA-04 `completePair` 重入 | 对已完成配对重复调用 3 次 | 三次返回同一结果；`pair_complete` 埋点**只上报一次** | 技术方案 3.3 / 第 9 章 |
| TC-PA-05 同一对好友重复配对 | 同一 (发起者, 受邀者) 二次发起 | 复用已有配对结果，不重复计算 | 3.3 |
| TC-PA-06 过期边界 | `now = expires_at ± 1s` 两种取值 | 等于 / 早于为有效；晚 1s 为过期 | 技术方案 3.3 |
| TC-PA-07 客户端改时间 | 篡改设备时间后请求 | 过期判定不受影响（以服务端时间为准） | 技术方案 3.3 |
| TC-PA-08 自配对 | 用自己的配对码进入配对流程 | 按产品结论处理：若关闭则返回 `PAIR_SELF_NOT_ALLOWED`（默认建议关闭，见技术方案 3.2 `[待确认]`） | 3.3 |
| TC-PA-09 配对码不存在 | 输入不存在的 8 位码 | 提示「邀请不存在」并引导重新发起，`PAIR_CODE_NOT_FOUND` | 6 错误码 |
| TC-PA-10 配对码字符集 | 输入含 `I / L / O / 0 / 1` 及大小写混合 | 输入容错处理正确（按规范归一化或明确拒绝） | 技术方案 3.5 |

## 6. 埋点验收与数据对账

### 6.1 事件逐条触发核对（12 个事件）

| 事件 | 触发路径 | 核对点 |
|---|---|---|
| `page_view` | 逐页进入 P-01→P-06 | 每页均有上报；`page_id` 正确；`entry_source` 可区分入口来源 |
| `test_start` | P-02 点击开始 | 携带 `entry_source` |
| `answer_submit` | 每题作答 | 10 次上报；`question_index` / `elapsed_ms` 合理 |
| `test_complete` | 结果生成瞬间 | `answer_count` = 10；`total_duration_ms` > 0 |
| `result_view` | P-04 展示 | 首次 `is_revisit` = false，重入为 true |
| `pair_invite_create` | 生成邀请 | `pair_code` 与页面展示一致 |
| `pair_invite_accept` | 受邀者接受 | `pair_code` 对应正确 |
| `pair_complete` | 图谱首次生成 | `c_count` / `band_label` / `similarity_pct` 与页面展示一致；**重入不上报**（对应 TC-PA-04） |
| `share_click` | 四渠道各点一次 | `scene` ∈ {result, pair}；`channel` 四值齐全 |
| `ad_impression` | 广告曝光 | `ad_type` / `placement` 正确 |
| `ad_reward` | 激励视频完播 | 仅自愿触发场景上报 |
| `session_end` | 切后台 / 退出 | `duration_ms` / `page_count` 合理 |

**公共字段完整性**：每个事件均须携带 `session_id`、`user_pseudo_id`、`app_version`、`quiz_version`、`ts`、`network`（PRD 第 9 章）。缺项即判缺陷。

### 6.2 指标换算对账

| 指标 | 对账方式 | 目标值 |
|---|---|---|
| 完测率 | `test_complete` ÷ `page_view`(page_id = P-03)，与看板数值比对 | `[TBD]`（D-4） |
| 分享率 | `share_click` ÷ `result_view` | `[TBD]`（D-4） |
| 停留时长 | `session_end.duration_ms` 均值 | `[TBD]`（D-4） |
| 配对发起率 / 配对完成率 / 次留 | 按 PRD 第 9 章定义逐项对账 | `[TBD]`（D-4） |

### 6.3 上报健壮性

| 用例 | 期望 |
|---|---|
| 埋点上报失败 | **不阻塞主流程**（UI 无感）；本地队列补传 |
| 队列超限 | 按上限丢最旧，不导致内存异常（上限 `[TBD]`） |

## 7. 合规实现层验收（红线，一票否决）

> 本章验证的是「机制是否真的生效」，与《合规资产-提审自检清单.md》第四节（内容与材料层）交叉复核，不重复但互相印证。

| 用例 | 方法 | 期望（关联需求） |
|---|---|---|
| TC-CM-01 免责常驻 | 逐页（P-01→P-06）截图 + DOM 核查 | 6 处均在位、字号 ≥ 24rpx、**无折叠交互**（4.4 / 8.2） |
| TC-CM-02 免责不可绕过 | 尝试通过样式覆盖缩小字号 | 组件样式锁定生效，外部无法覆盖（技术方案 8） |
| TC-CM-03 禁用词零命中 | 全量文案常量与可视文字扫描 | 8 个禁用词零命中；图内文字人工复核（4.3） |

| TC-CM-05 广告不改结果 | 走完全部广告路径 | 结果不因观看广告而改变；无「看广告改结果」入口（7.3） |

| TC-CM-07 无合盘 / 运势 / 吉凶 | 全功能遍历 + 全文案扫描 | **零命中**（8.3 红线） |
| TC-CM-08 图谱不做优劣 | 遍历同频度五档 | 各档视觉权重一致，**无红绿优劣区分、无排名** |

## 8. 缺陷分级与准入门禁

| 等级 | 定义 | 处置 |
|---|---|---|
| P0 阻断 | 红线合规失效（TC-CM 任一项不过）；主流程断（E2E-01 / 02 不通）；结果错误或不确定（TC-SC / TC-SM 不过）；重复出结果 | **不得提审**，修复后全量回归 |
| P1 严重 | 配对状态机异常、幂等失效、埋点缺失导致指标不可算、免责被遮挡 | 提审前必须修复 |
| P2 一般 | 文案错别字、动效不流畅、兼容性局部异常、非关键提示缺失 | 可带修复计划上线 |
